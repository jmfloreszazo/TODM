# TODM versioning and reproducibility

**Unified public research artifact version: 1.4.0 (28 October 2026).**

- **Methodology:** TODM v1.4; eight gates G0–G7, independent oracle baseline, greenfield/brownfield/AMS.
- **Research manuscript:** v1.4, canonical `paper/source/main.tex`, `paper/TODM_Paper_v1.4.md` and CI-generated `paper/TODM_Paper_v1.4.pdf`.
- **Demo:** v1.4 packaging, Python and .NET 10 engines, five limited JSON semantic profiles and 16 synthetic governance fixtures.
- **Legacy evidence format:** original prototype schema **v0.4**, retained for reproducibility in `demo/results/reproducibility-v0.4.json`, historical `demo/docs/*-v0.3.md` and `research-models/v0.4/`. These are **historical formats**, not the version of the published research artifact.
- **Canonical v1.4 evidence:** generated by `python3 demo/scripts/reproduce.py` as `demo/results/reproducibility-v1.4.json`, containing `version=1.4.0` and `profileSchemaVersion=0.4.0`.
- **GitHub release:** `todm-research-v1.4.0`, a new immutable tag; older tags `v1.2`, `v1.3`, `v1.4` are historical and not rewritten.
- **SHA-256 provenance:** the 88-file manifest includes versioned historical files as well as actively maintained source. Any intentional source change requires a corresponding hash update.
- **External scientific status:** arXiv submission and permanent DOI not yet completed; no industrial effectiveness claim.

Version consistency is enforced by `scripts/check_version_alignment.py` and the release pipeline. The release must be created **after** the v1.4 PDF is compiled and committed, never before.
