# TODM Open Research Challenge (proposal)

**Status:** open invitation for independent evaluation; no external validation is claimed.

**Research question:** Under which conditions do independently governed behavioral test oracles detect defects missed by tests generated alongside AI-produced software?

**Artifact:** TODM v1.5.0, DOI: https://doi.org/10.5281/zenodo.23725201

## Four tracks

1. **Reproduce:** run the published synthetic demonstration unchanged and document deviations.
2. **Falsify:** identify missed defects, false positives, ambiguous decisions, or oracle contamination.
3. **Compare:** preregister a controlled comparison with conventional and AI-generated tests; report precision, recall, time, and cost.
4. **Transfer:** evaluate applicability to an independently selected real-world system with appropriate authorization and privacy safeguards.

Start with [the protocol](PROTOCOL.md), then submit a report using [the template](RESULT_TEMPLATE.md). Consult [comparison baselines](BASELINES.md), [threats to validity](THREATS_TO_VALIDITY.md), and the canonical [comparative protocol](../../docs/COMPARATIVE_PROTOCOL.md). Submit reproducibility defects and counterexamples as GitHub issues using the dedicated issue forms. See invitations in [Spanish](INVITATION_ES.md) and [English](INVITATION_EN.md). Do not upload secrets, proprietary source code, or personal data.

**Negative, inconclusive, and positive findings are equally welcome.** Results remain attributed to their authors. No endorsement of TODM is implied by participation.
